## ADDED Requirements

### Requirement: 索引进行中展示可用文件列表

文件浏览器在后台索引尚未完成时，SHALL 尽快展示当前已可用的目录条目（至少包含工作区根下的直接子项）。面板 MUST NOT 在合法工作区根上仅以空白列表 + 永久 `indexing…` 作为唯一可见状态。

当后台仍在深化索引时，MAY 在根标签旁显示进行中指示；该指示 MUST NOT 阻止用户浏览与展开已展示的条目。

#### Scenario: 打开大体量工作区根

- **WHEN** 用户打开或树根切换到包含大量子树的目录（例如用户主目录）
- **THEN** 在短时间内侧栏出现该根下的直接子文件/文件夹列表，用户可以滚动与展开已加载的目录

#### Scenario: 深化索引不清空列表

- **WHEN** 浅层列表已显示且后台深扫仍在进行
- **THEN** 根标签可显示 indexing 指示，但已显示的文件行保持可见且可交互

### Requirement: Watch 重建不得导致永久 indexing

由文件系统 watch 触发的索引重建 SHALL 合并短时间窗口内的多次事件（防抖），并且 MUST NOT 将单纯的文件访问（`Access`）视为需要重建的变更。

当一次扫描正在进行时，新的变更 SHALL 排队为后续至多重扫一次，MUST NOT 以不断抬高扫描世代的方式使 loading 状态永远无法结束。

#### Scenario: 忽略 Access 事件

- **WHEN** watch 仅收到文件访问类事件
- **THEN** 系统不启动新的文件索引扫描，也不把面板切换到 indexing 阻塞态

#### Scenario: 频繁变更下防抖

- **WHEN** 工作区在数百毫秒内产生多次创建/修改/删除事件
- **THEN** 系统合并为有限次数的重建（防抖窗口内不逐事件全量重扫），文件列表最终与磁盘一致且 loading 能结束

#### Scenario: 扫描中的变更排队

- **WHEN** 全量或深扫进行期间又发生需重建的变更
- **THEN** 当前扫描被允许完成或被明确取代后，至多再触发一次后续扫描，面板不会无限停留在 indexing

### Requirement: 扫描完成路径始终刷新 UI

索引扫描的完成回调（成功、失败、结果被判定为过期）SHALL 使 UI 状态与模型一致。成功应用结果或进入失败/空闲时 MUST 通知视图重绘。

MUST NOT 出现模型已结束 loading 但界面仍显示 `indexing…` 且无文件行的卡住状态。

#### Scenario: 成功完成清除 loading

- **WHEN** 当前世代的索引成功完成并应用到工作区
- **THEN** indexing 指示按阶段规则更新或清除，文件列表反映索引结果

#### Scenario: 过期结果不破坏当前状态

- **WHEN** 较旧世代的扫描完成后发现已被更新的扫描取代
- **THEN** 回调丢弃该结果且不把当前面板错误地锁在 indexing

#### Scenario: 根无效时显示错误而非无限 loading

- **WHEN** 工作区根不存在或不是目录
- **THEN** 面板显示根无效错误，indexing 结束，不无限转圈

### Requirement: 深扫超时保留可用结果

对长时间无法完成的深扫，系统 SHALL 在软超时后停止以 indexing 阻塞用户，并保留已获得的可用列表（浅层或部分结果）。用户 MUST 仍能浏览已展示条目。

#### Scenario: 深扫超时

- **WHEN** 后台深扫超过实现设定的软超时仍未完成
- **THEN** 面板结束 deep-indexing 指示，继续展示已有条目，并可提示索引未完全完成
