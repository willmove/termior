# 内置运行时与外部 Agent 共用任务宿主

Termior 保留内置 Rust Agent 运行时,同时允许经结构化协议启动外部 Agent 子进程。两类后端统一映射为 Termior 的任务、Turn、事件、审批、终端和变更集模型;核心 GPUI UI 仍在主进程内,外部 Agent 的认证、模型和自身工具配置不被假定由 Termior 接管。

模型 API、MCP 与 Agent 宿主协议分属三层:模型 API 连接运行时与模型,MCP 连接 Agent 与工具/数据,ACP 或后端专用协议连接 Termior 与完整 Agent。首个专用适配器以 Codex app-server 的 stdio 协议验证深度集成,随后以 ACP 后端验证通用能力协商;普通 TUI Agent 继续作为 PTY 程序运行,不通过解析屏幕文本伪造结构化事件。

选择混合架构是因为完全重建成熟 Agent 的上下文压缩、恢复、生态和编排成本过高,而只托管第三方 Agent 又无法形成 Termior 的本地模型、终端协作与统一审阅能力。新增子进程边界修订了原规格中“AI Agent 运行时均在原生 Rust 模块中运行”的绝对表述,但不改变单进程原生 UI、BYOK、无托管代理服务和无通用 UI 插件市场的产品原则。

Termior 的审批策略与实际隔离始终分开表达。外部后端自行执行的命令不自动继承内置工具的路径门控;界面必须显示后端、执行环境、实际隔离能力和降级状态,且要求隔离的任务在对应能力不可用时必须拒绝启动,不得静默回落到直接执行。
