# SSH 与 SFTP

连接管理有三个入口：标签栏 **＋旁的下拉菜单 → SSH / SFTP 连接…**、
**系统偏好设置 → General → SSH / SFTP**，以及左侧 **SSH / SFTP → 管理连接…**。
左侧采用紧凑单行列表，默认每个配置只显示一个 SSH 入口，避免重复的 SFTP 项占用空间。
单击仅选中，鼠标左键双击连接 SSH；右键菜单提供「连接 SSH」「以 SFTP 连接」、
「重命名」「编辑会话」「移动到分组」「删除会话」。重命名和编辑打开并定位到对应配置，保存后生效；
删除需确认，既有连接不受影响。「已打开会话」列表单击切换现有标签，不新建连接。
保存、编辑或删除后列表立即更新。小窗口支持右侧滚动条拖动及滚轮，窄窗口自动上下排列；
Tab/Shift+Tab 切换输入框并滚动到焦点，长输入内容随光标横向滚动。

## 连接分组

每个连接可归属一个分组或保持未分组。未分组连接列在最前，其后按分组顺序展示；
分组表头显示名称与成员数，单击折叠/展开（折叠状态不跨重启保存），右键提供
「重命名分组」和「删除分组」——重命名与现有分组重名即合并，删除分组时其成员
归入未分组；连接的删除、移动不影响分组本身。分组独立于连接持久化，允许空分组；
组内最后一个连接被删除后分组依然保留。侧栏底部「＋ 新建分组」与连接右键
「移动到分组 → 新建分组…」都通过命令栏输入新分组名，后者同时把该连接移入。
管理窗口表单的「分组」字段可直接输入已有分组名或新名称（保存时自动建组），
留空表示未分组。分组名限 1–64 字节、无控制字符、首尾无空白。

## 连接和认证

填写连接名称和主机。主机可填写 DNS、IPv4、IPv6 或现有 OpenSSH `Host` 别名，
不要把 `user@` 或端口拼进主机字段。用户名、端口留空时沿用 SSH config。
可设置私钥路径以及 `user@bastion:2222` 形式的跳板机；多个跳板用逗号分隔。
点击保存持久化配置；连接和选择传输文件前也会保存当前配置。

- 自动：沿用 OpenSSH 认证能力，包括 SSH config、agent 和默认密钥。
- 密码 / MFA：使用 keyboard-interactive/password。
- 密钥：使用指定密钥，支持加密私钥，保留 MFA/密码后续认证。
- SSH Agent：仅使用 agent 提供的公钥身份；先用系统 `ssh-add` 管理密钥。

点击「连接 SSH」或「打开 SFTP」，在统一的「SSH 身份认证」窗口完成主机指纹、
密码、口令或 OTP 输入；终端不再同时索要登录密码。相同目标的终端、Explorer 和
传输 Tab 共用认证协调器，普通密码/指定私钥口令只输入一次。首次指纹请通过可信渠道
核对；已知密钥变化时 OpenSSH 拒绝连接。
认证窗口可勾选「记住密码（保存到系统凭据库）」；连接管理也可预先启用
「记住密码和私钥口令（系统凭据库）」。首次输入即保存，后续显式重连（包括应用重启后）
自动读取。未勾选时只在内存复用，关闭最后一个同目标会话后清除。输入框始终遮蔽
凭据；连接管理中的密码字段留空保留已有凭据。
Windows 使用 Credential Manager，macOS 使用 Keychain，Linux 使用系统密钥服务；
系统凭据库不可用时明确报错，不回退为明文文件。配置、环境变量、命令行和终端输出
不包含凭据。私钥文件继续由 OpenSSH/SSH Agent 使用，应用不复制私钥内容。

无论是否启用保存，OpenSSH 均通过统一认证窗口请求缺失或被拒绝的凭据；首次主机指纹仍须确认，
OTP 和任意 keyboard-interactive 提示不会从密码库自动填充。普通 password 认证优先于
keyboard-interactive（公钥仍优先）。代理/跳板连接因 OpenSSH 无法向认证助手区分来源跳，
仍需手动输入或使用 SSH Agent，避免把目标密码交给跳板机。

「清除该连接的已保存凭据」删除对应目标的密码与私钥口令；关闭保存选项并保存、
删除连接或修改目标后，会清理不再被其他已保存配置引用的旧凭据。重命名连接可继续复用，
修改主机、用户、端口、私钥或跳板机不会把旧密码带到新目标。Termior 不保存 OTP，
也不会自动删除 known_hosts 记录。

标签后台保持连接，分栏打开独立会话。断开或关闭标签会终止其连接；失败/退出保留
终端输出。重新连接为显式操作。重启只恢复连接信息，不自动登录或重放传输。
连接管理的删除只删配置，不终止既有连接。

## 文件传输

在连接管理填写「SFTP 远程路径」：上传时是目标路径，下载时是源路径。
点击「选择上传…」或「下载到…」，通过系统文件对话框选本地文件，核对显示的
方向、路径和覆盖说明后点击「确认路径并开始传输」。每个传输占一个独立标签，
可以并行运行，在终端中查看进度和诊断；状态由 OpenSSH 的退出码判定。

勾选「整个目录」进行递归传输。已有目标目录时遵循 OpenSSH SFTP 的目录嵌套语义。
勾选「断点续传」只适用于已有内容确实是源文件相同前缀的情况；不验证这一点会
造成损坏。默认传输会覆盖目标同名文件。取消/连接中断可能留下部分文件，
之后由用户决定重新传输或续传；应用不会自动重试。

「打开 SFTP」或右键「以 SFTP 连接」在主区域打开图形化双栏文件浏览器，
不再打开 `sftp>` 命令行：

- 左栏为本地文件，右栏为远程文件，按名称、类型、大小列展示；目录优先排列。
- 单击选中，双击文件夹进入；上级、刷新按钮和远程「转到路径」支持目录导航，
  本地「选择目录」可以切换磁盘和任意本地目录。隐藏文件及被 Git 忽略的文件也显示。
- 从本地拖到远程栏上传，从远程拖到本地栏下载；拖到文件夹行时，以该文件夹为目标，
  拖到列表空白处时以当前目录为目标。目录自动递归。也可把系统文件管理器中的文件或
  文件夹拖到远程栏上传。上传符号链接会明确报错，请选择实际文件/目录。
- 上传/下载按钮使用选中条目和另一栏的当前目录。每次拖放先确认方向、路径和覆盖说明，
  确认后在后台建立传输标签，保持文件浏览器可见。底部显示传输状态，可取消或点击
  「查看进度」打开详细输出；完成后刷新目录。取消或中断可能留下部分文件。
- 远程右键支持打开文件夹、新建文件/文件夹、上传文件/文件夹、下载、重命名、移动、
  删除及刷新；远程删除会再次确认。重命名/移动的输入区在主区域显示，Enter 提交、Esc 取消。
- 浏览会话只使用一条后台 SFTP 连接，不额外启动交互 SFTP PTY。切换标签保留浏览状态，
  返回时刷新本地列表，传输完成使远程缓存失效；断开停止后台连接，重连须显式操作。
  应用重启只恢复断开的标签，不自动连接或重放传输。

当当前活动 Tab 是 SSH 或 SFTP 会话时，左侧 **File Explorer** 自动显示同一主机的
远程目录，而不是本地 `project_dir`。远程 shell 提供 OSC 7 cwd 时跟随该目录；否则
从 SFTP 登录目录开始。双击文件夹进入，顶部向上箭头返回父目录；右键可新建文件/文件夹、
重命名、移动、递归删除、上传文件/文件夹或下载。上传和下载仍建立独立传输 Tab，并在
可能覆盖现有目标前确认。切回本地 Tab 后，本地文件树立即恢复。

Explorer 为每个 Tab 保留一条后台 OpenSSH SFTP 连接，目录切换和文件管理复用它，
不再为每个目录重新启动客户端或重新认证。通过 SFTP v3 协议读取文件属性，不解析
`ls` 文本、不拼接远端 shell 命令。Windows 后台进程不创建系统命令行窗口。

侧栏显示连接/等待认证、已读取条目和已完成操作数量；请求期间顶部 × 可取消。
每次请求最多 5 分钟（含认证等待），网络建连另受配置中的连接超时约束；取消、超时、
断线和权限错误均显示在侧栏，失败后点刷新显式重试，不自动重放文件操作。
取消或超时不代表撤销：已完成的远程删除/移动等可能保留，重试前先刷新核对。
关闭或断开 Tab 会终止后台连接及它的认证提示，不影响其他 Tab。

目录缓存有效期 30 秒，每个 Tab 最多 32 个缓存键/50,000 条记录；刷新绕过缓存，
文件管理及传输结束使缓存失效。连续点击合并相同请求，只保留最新的待浏览目录。
单目录最多读取 20,000 条，递归删除最多 20,000 项、128 层，不跟随符号链接，
不允许递归删除远程根目录；新建文件不会清空已有文件，移动/更名不覆盖同名目标。

后台 SFTP 与终端 PTY 仍是独立网络连接，但共享认证入口与内存凭据，普通密码不会
因同时打开两者而重复询问。取消认证会拒绝该次登录已启动的其他认证请求；之后仍可
显式重连。OTP/未知 keyboard-interactive/跳板提示不缓存，可能逐连接询问，不能承诺
所有认证仅发生一次。系统凭据库保存失败时明确报错，可取消勾选，仅本次使用。

## 平台和边界

本机须安装 `ssh` 和 `sftp` 并可从 PATH 启动。Windows 可使用系统 OpenSSH Client，
macOS 通常自带，Linux 可安装发行版 OpenSSH 客户端包。传输任务要求支持 `-N` 的
SFTP 客户端；验证版本为 Windows OpenSSH 9.5p2。缺少程序或版本不兼容时标签中
显示失败诊断，不自动安装或更改系统设置。

连接配置保存在应用数据目录的 `Termior-ssh.json`，schema v2。v1 文件在下次读取时
自动迁移；较新或无效 schema（含引用不存在分组的连接）会显示错误并禁止覆盖原文件。
顶层 `groups` 数组按展示顺序持久化分组列表；连接对象的可选 `group` 字段引用分组名，
缺省或空串表示未分组。可选高级 JSON 字段 `connect_timeout_secs`（1–300，
默认 15）、`keepalive_secs`（1–3600，默认 30）和 `known_hosts_file`（默认空，
沿用系统配置）。默认不转发 agent、X11 或端口；这不是端口转发管理器。

SSH/SFTP 属于用户控制的远程会话；File Explorer 仅在活动远程 Tab 中切换为该主机的
SFTP 视图，Git、Composer Agent 与 `project_dir` 仍在本机。远端 OSC 7 只更新该 Tab
的远程 Explorer 路径；其他远端 OSC 和 localhost 输出不会重定向本地上下文。本轮没有
远程 Agent、远程编辑器或无人值守的后台传输服务。双栏文件浏览不会改变本地 Git/Agent 项目范围。Windows OpenSSH 会改写
字面反斜杠，因此这种罕见远端文件名被拒绝，避免传错文件。

## 验证

```powershell
cargo test -p termior-ssh -p termior-terminal -p termior-ui -p termior-explorer
cargo test -p termior sftp_browser
cargo check -p termior
python -m venv target/ssh-test-venv
target/ssh-test-venv/Scripts/python.exe -m pip install paramiko==5.0.0
$env:TERMIOR_SSH_TEST_PYTHON = (Resolve-Path target/ssh-test-venv/Scripts/python.exe).Path
cargo test -p termior-terminal --test ssh_roundtrip -- --ignored
```

Unix 将变量设为相应 venv 的 `bin/python`。fixture 仅监听 loopback，生成临时
host key、用户密钥、known_hosts 与文件，不接触真实主机或用户 SSH 配置。
测试覆盖生产 PTY 上的密码、MFA、加密私钥认证、resize、文件字节一致性、中文/空格/方括号名称、
续传、递归传输、失败退出码与变更 host key 拒绝。
Explorer 回归还验证持久连接计数、缓存/强制刷新/写后失效、特殊文件名、已有文件
防截断、普通错误后连接复用、服务端卡住时的取消和超时、显式恢复以及关闭后拒绝新请求。
设置 `TERMIOR_SSH_ASKPASS_EXE` 为构建后的 Termior 可执行文件路径，可额外测试真实
系统凭据库中的密码/私钥口令在连续 SSH 连接及 SFTP 下载中复用，以及终端与 Explorer
并发连接只询问一次、新协调器从凭据库自动认证；测试凭据结束后删除。运行
`cargo test -p termior first_prompt_remember -- --ignored` 可验证首次提示的保存/清除流程，
该测试也仅创建并清理隔离的测试凭据。
macOS/Linux 尚需在对应平台运行。

Windows 本机已通过上述真实连接测试、相关 crate 回归测试、桌面测试和 Clippy。
连接管理输入的中文/emoji 光标、IME 替换、高级配置保留、小窗口滚动和长输入光标也有 GPUI 控件测试。
此前桌面截图工具对 GPUI 窗口返回黑帧；本次隔离启动未暴露可捕获窗口，
