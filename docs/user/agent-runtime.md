# Agent 扩展、恢复与本地自动化

Termior 的 Composer 提供内置 Agent、结构化外部后端及其任务状态。使用外部后端前先安装并完成该后端自己的认证；后端可用性、模型与权限以握手后的能力档案为准。普通终端中的 CLI Agent 仍使用自己的执行通道。

## 扩展来源与权限

在用户目录或项目的 `.agents/skills/<name>/SKILL.md` 安装 Skill。同名时项目版本优先；Composer 的 `Skills N` 显示来源与工具限制。在消息里显式写 `$<name>` 激活后，正文才进入本 Turn 的上下文。Skill 的 `allowed-tools` 只能缩小任务工具集合，不能增加权限。

Settings 的 Agents 页面可查看 MCP 认证状态、登录/退出，以及启停生命周期 Hook 和查看运行记录。MCP 连接定义在应用数据目录的 `mcp-servers.json`，Hook 定义在 `Termior-lifecycle-hooks.json`。只启用你信任的服务与脚本：stdio server 和 Hook 是本机进程，安装它们不等于为其建立操作系统 sandbox。远端 MCP 使用 HTTPS（localhost 例外），凭据存系统钥匙串，配置仅保存凭据引用。Hook 超时或失败会留下记录；Hook 改写工具参数后必须重新校验并按最终参数审批。

内置工具执行仍受 workspace 授权、路径限制、secret deny-list 和网络策略约束。外部 Agent 自行执行的命令不自动经过这些门控；查看环境 chip 的 host、root、能力及 verified/reported/unknown 状态，再决定是否运行。

排障时先检查 `Context`、`Skills`、MCP/Hook 管理列表及错误记录：确认来源是否正确、服务是否启动、协议是否匹配、能力是否声明。连接失败后先处理认证或版本问题，再显式重连。不要把 API key 放进消息、项目规则、Skill 或日志。

卸载 Skill 时移除对应安装目录；移除项目副本后，同名用户副本可能重新可用。停用或移除 MCP/Hook 配置后重启应用，确保旧连接不再使用。撤销远端 token 或清除系统钥匙串中的对应凭据需要单独处理；删除配置不等于撤销远端授权。历史任务、审计与文件修改不会因此自动删除或回退。

## 审批与执行环境

Auto 对需要批准的操作等待用户；Plan 的计划确认前不执行写操作；Yolo 会自动放行门控操作和变更审阅，但仍保留内置安全限制。审批允许某次操作，不代表操作系统限制了该进程的全部能力。

| 执行环境 | 文件与外部副作用边界 |
|---|---|
| direct | 在任务绑定的本地目录执行；没有独立文件系统或网络隔离 |
| worktree | 使用独立 Git 工作目录便于审阅与合入；进程仍可能访问宿主资源 |
| sandboxed | 仅在平台提供任务要求的已验证能力时启动；能力不足则拒绝执行 |

Windows 当前只有进程树控制，文件、网络、凭据隔离为 unsupported。Linux 依赖 `bwrap`，macOS 依赖 `sandbox-exec`；部署环境缺少依赖或无法建立隔离时，要求 sandbox 的任务会失败，不会回落 direct。详细验证条件见 [Stage D 验证指南](../process/ai-agent-stage-d-validation.md)。

## 检查点与崩溃恢复

文件修改应用前检查基线；用户已修改同一文件时进入冲突处理。`Checkpoints N` 中的 `Restore unchanged outputs` 只恢复仍符合 expected-after 的文件；用户后来改过的文件会报告冲突并跳过。检查点不撤销已发出的网络请求、数据库写入、部署或其他外部副作用。

崩溃后，`Recovery N` 展示未完成任务。无法确认结果的活动操作恢复为 unknown，系统不自动重放。先检查文件、进程和外部服务状态，再选择放弃或准备新的 attempt；准备重试本身不证明旧操作没有生效。

## 并行任务与预算

`Task tree N` 展示子任务依赖、后端、环境、预算、验证结果及排队原因，可调整并发上限或取消任务。子任务只能继承相同或更小的权限与预算。写子任务使用独立 worktree 或显式写租约；结果过期、验证未通过或合入有冲突时，父任务不能直接接受。

任务达到预算时暂停或等待处理。取消是尽力停止，尚未确认终止的副作用保持 unknown。未知 token 或费用显示为 unknown，不能据此认定没有消耗。

## 本地自动化

在 `Automations N` 查看模板、next run、last runs 和磁盘预算。每次运行有独立 task/run ID，运行中的任务固定使用创建时的模板版本、后端、权限与预算。编辑模板不会扩大已运行任务的权限。

自动化仅在 Termior 运行时调度。关闭应用后没有后台守护进程执行任务；重新启动时按显式 catch-up 策略跳过、补一次或在配置上限内补跑。相同 dedupe key 会去重，事件风暴会合并。

仅结果已知、幂等的 transient 失败允许自动重试；unknown 结果等待用户，已知非幂等失败停止自动重试。处理前应核对外部状态，避免重复付款、提交或部署等副作用。等待审批不自动批准，也不弹出不可见的模态框。

通知按策略发送完成、失败和需要处理的状态。开始及 working 更新汇总到铃铛，不触发应用内或系统弹窗；关闭通知不停止任务。界面可见性还会影响弹窗投递方式。
